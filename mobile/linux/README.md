# Quantway для Linux — прототип

Приложение с нативным интерфейсом GTK 4 использует общий с Android парсер подписок и VPN-движок. Можно войти по коду Quantway или добавить полную ссылку стороннего провайдера. Вход в Quantway сохраняется между запусками в системном хранилище паролей Linux (Secret Service: например, GNOME Keyring). Код входа не сохраняется; ссылки сторонних провайдеров остаются в памяти процесса до закрытия приложения.

## Установка DEB-пакета

Пакеты для Ubuntu Desktop 22.04 и новее находятся в
`bin/quantway-linux-client/deb/`. Для `aarch64` выбирайте файл с окончанием
`_arm64.deb`, для `x86_64` — `_amd64.deb`. Архитектуру показывает команда
`dpkg --print-architecture`. Скачайте один подходящий файл и установите его
через `sudo apt install ./имя-файла.deb`: APT подтянет зависимости.
Quantway появится в меню приложений; из терминала он запускается командой
`quantway`, без `sudo`. Отдельно запускать `setup-vm.sh` для DEB не нужно.

Перед обновлением или удалением отключите VPN и закройте Quantway. Пакет
сохраняет ключи устройства и пользовательские данные при удалении. Приложение
по-прежнему запрашивает разрешение администратора при включении VPN.

Сборка обоих DEB-пакетов: `sh mobile/scripts/build-linux-deb.sh all` из корня
репозитория. Нужны Go с поддержкой версии из `mobile/go.mod`, Python 3.9+,
Git и Docker. Сборщик проверяет входной архив, архитектуры и контрольные суммы;
исходники поставляемого tinc и лицензии зависимостей включаются в пакет.
Версию и каталог результата можно задать через `QUANTWAY_DEB_VERSION` и
`QUANTWAY_DEB_OUTPUT_DIR`. Шаблоны и детали пакета — в `debian/README.md`.

## Установка готового архива

Для Ubuntu Desktop доступны отдельные архивы `quantway-linux-arm64.tar.gz` и `quantway-linux-amd64.tar.gz`. Архитектура должна совпадать с компьютером: `aarch64` — ARM64, `x86_64` — AMD64. Нужны Python 3.9+, PyGObject, GTK 4, PolicyKit (`pkexec`), `iproute2`, `nftables` и работающий `systemd-resolved` с `resolvectl`.

В каталоге с архивом и опубликованным `SHA256SUMS` проверьте контрольную сумму, распакуйте архив и установите помощники. Пример для ARM64:

```sh
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf quantway-linux-arm64.tar.gz
cd quantway-linux-arm64/mobile/linux
./setup-vm.sh --check
./setup-vm.sh
./run.sh
```

Пароль администратора нужен только для установки. Интерфейс запускается обычным пользователем; при явном подключении системное окно PolicyKit подтверждает запуск сетевого помощника. Установщик проверяет файлы архива и архитектуру, затем устанавливает `quantway-net-helper`, `quantway-tinc-helper`, `tinc` и `tincd` в `/usr/libexec/quantway` с владельцем `root` и правами `0755`. Он отказывает при символических ссылках или доступных пользователю для записи каталогах установки. Установка не подключает VPN, не добавляет разрешающих правил PolicyKit и не перезапускает приложения.

Сохраняйте структуру распакованного архива: интерфейс использует `mobile/linux/build/quantway-helper` и изображение из `mobile/android/app/src/main/res/drawable`. Обновление выполняется повторной установкой помощников из нового проверенного архива после отключения VPN и закрытия Quantway. Архив не содержит аккаунтов, ссылок, ключей или состояния подключения. Контрольные суммы проверяют целостность; получайте архив и суммы из доверенного источника.

## Если Tinc сразу выдаёт ошибку

Системный помощник устанавливается отдельно от интерфейса. Обновление файлов в общей папке Parallels само по себе не обновляет `/usr/libexec/quantway/quantway-tinc-helper` в Ubuntu. Если он отсутствует, подключение останавливается до запроса пароля. Из проверенного архива или синхронизированной рабочей сборки выполните `./setup-vm.sh`, затем перезапустите Quantway обычным пользователем. Пароль вводится только в Ubuntu и не передаётся приложению.

Интерфейс отдельно сообщает об отсутствующем помощнике, небезопасных правах, отмене системной авторизации и недоступных сетевых компонентах. В сообщения не попадают ключи, ссылки подписки и необработанный вывод системных команд. Запускайте интерфейс без `sudo`; повышение прав происходит только при установке и подключении.

## Сборка

Из корня репозитория:

```sh
./mobile/scripts/build-linux-client.sh arm64
# либо amd64 / all
```

Результат находится в `bin/quantway-linux-client/`: архив для выбранной архитектуры и `SHA256SUMS`. Скрипт собирает три Go-помощника и использует проверенные нативные `tinc`/`tincd` из `bin/quantway-tinc-linux/linux-<arch>`; при их отсутствии вызывает `build-tinc-linux.sh`, для которого нужен Docker. Исходная версия tinc закреплена в `mobile/native/tinc/source-pin.env`; архив включает лицензию `COPYING.tinc`, сведения о версии `BUILD-INFO.tinc` и контрольные суммы локальных Go-исходников `BUILD-INFO.client`. Изменение этих исходников во время сборки останавливает упаковку. В пакет входят только исполняемые файлы, исходники интерфейса, стили, документация и изображение.

Для разработки интерфейса и тестов из каталога `mobile`:

```sh
go test ./linux/...
mkdir -p linux/build
go build -o linux/build/quantway-helper ./linux/cmd/quantway
./linux/run.sh
```

Низкоуровневый слой создаёт Linux TUN, поднимает Xray или AWG и добавляет маршруты с откатом. Для изменения маршрутов и DNS используется отдельный привилегированный сетевой помощник `quantway-net-helper`; VPN-конфигурации и ключи ему не передаются. Для его установки используйте собранный архив с полным `SHA256SUMS`.

## Отдельный режим Tinc

На «Главной» для текущего устройства Quantway доступны выбор режима «Обычный VPN» / «Tinc», страна выхода и общая кнопка подключения. После отключения выбранный режим сохраняется; следующее подключение Tinc не запускает Xray. Смена режима или страны при работающем VPN требует подтверждения и завершения прежнего соединения.

Раздел «Tinc» в боковом меню сразу под «Главная» показывает состояние меша: подтверждённые соединения со входами, назначенную страну выхода, локальные объёмы и скорость трафика VPN-интерфейса. Снимки обновляются локально без дополнительных запросов к серверному API. Недоступные или устаревшие наблюдения отмечаются как неизвестные. Внутренние переходы между серверами не наблюдаются клиентом, поэтому интерфейс не рисует их как установленный маршрут. Для новых счётчиков нужны помощники из текущего архива; старый помощник показывает только известные ему подключения.

Клиентский Tinc использует собственный привилегированный `quantway-tinc-helper` и входит в тот же архив. Доступ определяет сервер для текущего устройства Quantway: активная подписка и доступные по тарифу страны. Каталог стран загружается до регистрации локального ключа; приложение не задаёт список стран самостоятельно. Ключ устройства хранится отдельно у `root` в `/var/lib/quantway-tinc/users/<UID>/<device UUID>`, поэтому перевыпуск ссылки устройства не создаёт новую идентичность. Ссылки и временные учётные данные передаются помощнику в памяти и в архив не попадают.

В этом режиме все пользовательские соединения проходят через TUN, клиент видит входы пилота, а сервер назначает выход в выбранной для устройства стране. Входы и выходы принимают доступ только по ограниченной по времени конфигурации; ошибка API не продлевает её. Истечение доступа блокирует трафик, отключение удаляет принадлежащие режиму интерфейсы и правила. Оба сетевых помощника используют одну блокировку, чтобы обычный режим и Tinc не изменяли маршруты одновременно. Пилот поддерживает IPv4; IPv6 пользовательского трафика блокируется на время подключения. Внешний транспорт Linux-прототипа использует TCP для устойчивой работы за NAT. TCP- и UDP-трафик приложений передаётся внутри этого защищённого соединения; задержка при потере TCP-пакетов может увеличиваться.

Доступ к отдельному серверному слою открыт всем аккаунтам с активной подпиской. Одновременно слой обслуживает до 16 устройств; при занятости приложение сообщает об этом до включения TUN и повторяет запрос, поэтому обычный интернет остаётся доступным. Полный Android TUN и мобильный выбор входов остаются отдельными этапами. Проверка серверного пилота и самостоятельного Linux-клиента описана в `docs/audits/2026-10-31-client-tinc-pilot.md` в репозитории; готовый архив интерфейса проверяется отдельно.

## Работа с приложением

Для интерфейса нужны Python 3, PyGObject и GTK 4. Ссылка хранится только в памяти на время работы приложения.

Для сохранения входа нужен работающий Secret Service в пользовательской D-Bus-сессии. В Ubuntu Desktop обычно используется GNOME Keyring; если его нет, установите пакет `gnome-keyring` и войдите в графическую сессию заново. Приложение обращается к хранилищу через уже имеющийся GIO, отдельный Python-модуль keyring не нужен. Если хранилище недоступно или пользователь отменил разблокировку, кабинет открывается на текущий запуск, а приложение явно предлагает повторить сохранение; незащищённого файла с cookie нет.

При запуске сохранённая cookie проверяется сервером, кабинет обновляется и используется существующая привязка этого компьютера. Восстановление не создаёт новое устройство. Если пользователь уже выбрал стороннего провайдера, фоновый вход его не переключает. Временная сетевая ошибка сохраняет вход и позволяет повторить восстановление; недействительная сессия требует нового кода. Закрытие окна сохраняет вход, а «Выйти из аккаунта» отключает автоматический вход даже без сети и удаляет запись хранилища. Пустой файл `~/.config/quantway/session-autologin-disabled` содержит только настройку запрета восстановления на случай недоступного хранилища при выходе.

Стартовый экран разделяет два сценария: вход в Quantway и подключение внешнего провайдера. Внешние подписки находятся в отдельном разделе «Другие VPN»: список провайдеров, выбор активного, обновление маршрутов, изменение названия или ссылки и удаление из приложения. Их ссылки не передаются API кабинета.

При входе в кабинет текущий компьютер привязывается к устройству аккаунта; VPN включается отдельно. Выбор устройства для замены показывается при нехватке мест. Полное управление доступно в отдельном разделе «Мои устройства»: создание, переименование, блокировка, разблокировка, перевыпуск ссылки, удаление, ссылка и QR-код для подключения, покупка дополнительного места. Изменяющие доступ операции требуют подтверждения. При заполненных местах основным действием становится покупка места; ссылка и QR доступны непосредственно в карточке устройства.

В кабинете доступны остаток дней, продление, счета, промокоды, пауза подписки, поддержка с изображениями, приглашения, Telegram и обновление кода входа через существующие серверные API. Действия учитывают роль и включённые сервером возможности. Переход к оплате открывает браузер.

Карточка подписки показывает трафик аккаунта и профиля этого компьютера с начала месяца, занятые места и устройства в сети. Статистика загружается из списка устройств Quantway; трафик внешних провайдеров в неё не входит. Неизвестные значения обозначены прочерком, а при неудачном обновлении сохранённые данные отмечаются как последние полученные.

Поддержка оформлена как нативный чат: история сообщений прокручивается отдельно от поля ввода, ответы команды и сообщения пользователя расположены по разным сторонам. Enter отправляет сообщение, Shift+Enter добавляет строку. Пока чат открыт, ответы обновляются каждые восемь секунд; обновление сохраняет черновик и позицию чтения, а отправка имеет приоритет перед фоновой загрузкой.

После загрузки подписки приложение проверяет маршруты через общий движок (до десяти одновременно), показывает реальный прогресс и выбирает доступный вариант с лучшим временем проверки. На Главной источник, способ подключения и назначение расположены перед закреплённой кнопкой Connect/Stop. Другие маршруты доступны в раскрываемом списке. Значение «Проверка: … мс» обозначает длительность проверки, а не текущий ping или скорость VPN.

В разделе «Маршруты» есть поиск по названию/технологии и фильтр доступности. В активной сессии перемещение по списку только просматривает кандидата. Для смены нужно явно нажать «Переключить маршрут» и подтвердить действие; приложение дождётся завершения старого соединения. Проверка маршрутов доступна при выключенном VPN. Автоматический повтор при смене сети пока не реализован в Linux.

Компоновка и стили находятся в `ui/desktop_ui.py` и `ui/desktop.css`, операции и состояние — в `ui/quantway.py`. Узкое окно переключается на компактную навигацию и одну колонку; шрифты учитывают системный масштаб текста.

Кнопка подключения остаётся видимой при прокрутке настроек, включая увеличенный текст. Проверка маршрутов и переход к монитору находятся рядом с настройками назначения. Рутинные подсказки не занимают постоянный баннер; полное сообщение об ошибке открывается отдельной доступной с клавиатуры кнопкой. Действия подписки и оплаты сгруппированы по задачам, а редкие и опасные действия находятся в раскрывающихся разделах. Панели действий переносят кнопки при нехватке ширины и пропускают скрытые/отключённые элементы при Tab. История поддержки прокручивается отдельно от редактора; сообщения сохраняют разное выравнивание и ограниченную читаемую ширину.

Проверка интерфейса в Linux с GTK 4 и Xvfb:

```sh
xvfb-run -a python3 ui/test_smoke.py
xvfb-run -a python3 ui/test_live_switch.py
xvfb-run -a python3 ui/test_device_ui.py
xvfb-run -a python3 ui/test_cabinet_ui.py
xvfb-run -a python3 ui/test_support_chat.py
xvfb-run -a python3 ui/test_session_store.py
xvfb-run -a python3 ui/test_auth_persistence.py
xvfb-run -a env GSK_RENDERER=cairo python3 ui/test_disclosures.py --output /tmp/quantway-disclosures
xvfb-run -a env GSK_RENDERER=cairo python3 ui/qa_screens.py --output /tmp/quantway-ui
```

`qa_screens.py` снимает настоящие GTK-виджеты с автономными тестовыми данными. Он не обращается к сети, кабинету или VPN. Эти изображения подтверждают компоновку, но не заменяют проверку подключения с реальной подпиской. Для проверки символических значков и флагов нужны `adwaita-icon-theme` и `fonts-noto-color-emoji`.
