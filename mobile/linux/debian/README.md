# Шаблоны Debian-пакета Quantway

Версия предпросмотра: `0.7.1~preview20261101.2`. Архитектуры пакета: `arm64`
для Linux `aarch64` и `amd64` для Linux `x86_64`. Проверены чистая установка,
жизненный цикл пакета и запуск интерфейса в Ubuntu 22.04 на обеих архитектурах;
установка и запуск также проверены в Ubuntu 24.04 ARM64. Наличие `.deb` само
по себе не подтверждает поддержку любой Debian-подобной системы.

## Подстановка и размещение

`control.in` содержит только `@VERSION@`, `@ARCHITECTURE@`, `@MAINTAINER@`
и `@INSTALLED_SIZE@` (размер установленного payload в КиБ). Значение Maintainer
по умолчанию — `Quantway`; реальное значение можно передать сборщику отдельно.

В `preinst.in` и `prerm.in` сборщик заменяет ровно один `@MAINTAINER_CHECK@`
полным текстом `maintainer-check.py` и записывает полученные `DEBIAN/preinst`
и `DEBIAN/prerm` с режимом `0755`. Проверка встроена в каждый скрипт: `preinst`
не зависит от ещё не распакованных файлов нового пакета. Для неё объявлен
`Pre-Depends: python3-minimal (>= 3.9)`. Шаблон `prerm` проверяет также
`failed-upgrade`, чтобы резервный путь dpkg не обходил отказ занятого клиента.

Рекомендуемый payload:

- `/usr/bin/quantway` — файл `quantway`, `root:root`, `0755`;
- `/usr/libexec/quantway/` — пять настоящих исполняемых файлов
  `quantway-helper`, `quantway-net-helper`, `quantway-tinc-helper`, `tinc`,
  `tincd`, все `root:root`, `0755`, без символических ссылок;
- `/usr/share/quantway/mobile/linux/ui/` — рабочие Python-модули и CSS,
  без тестов и `__pycache__`, `root:root`, `0644`;
- `/usr/share/quantway/mobile/android/app/src/main/res/drawable/quantway_brand.png`
  — изображение для текущего относительного пути интерфейса;
- `/usr/share/applications/link.quantway.desktop.desktop` — шаблон desktop entry;
- `/usr/share/icons/hicolor/512x512/apps/quantway.png` — то же изображение 512×512;
- `/usr/share/doc/quantway/` — этот README, `copyright`, `COPYING.tinc`
  и метаданные исходников `BUILD-INFO.client` / `BUILD-INFO.tinc`.

Каталоги пакета должны быть `root:root`, `0755`, включая установку при
`umask 077`. Существующие глобальные каталоги не нужно рекурсивно менять
через `chmod`/`chown`. Контрольные суммы и архитектуры ELF проверяются до
сборки пакета; архив dpkg должен сохранять владельца `root:root`.

Launcher фиксирует `QUANTWAY_HELPER` и запускает интерфейс обычным пользователем
через `/usr/bin/python3 -B -E -s`. `-B` исключает запись bytecode в пакет,
`-E -s` отключают Python-переменные среды и пользовательский site-packages,
сохраняя импорт соседних модулей. Простой `python3 -I app.py` здесь не подходит:
он убирает каталог скрипта из путей импорта.

## Зависимости и DNS

GTK 4.6+ и GIO 2.72+ — минимумы для варианта с совместимыми fallback; старые
библиотеки не должны получать современный пакет без этих fallback. SVG QR-коды
загружаются через GdkPixbuf, поэтому `librsvg2-common` обязателен. Нативные Go
помощники и поставляемый tinc статически собраны: отдельный Xray, системный tinc,
компилятор и Python-модуль keyring для запуска не нужны.

Нужны `/dev/net/tun`, PolicyKit с агентом аутентификации графической сессии,
`ip`, `nft`, работающий `resolvectl` и настроенный systemd-resolved. Обычный VPN
проверяет, что `/etc/resolv.conf` использует stub `127.0.0.53` или `127.0.0.54`.
У Ubuntu 22.04 есть пакеты `pkexec`, `polkitd` и `policykit-1`, а `resolvectl`
поставляется в `systemd` версии 249. Два условия Depends для resolver разрешают
такой старый поставщик только в диапазоне `[249, 250)`. На новых системах
зависимость требует отдельный `systemd-resolved`; один установленный `systemd`
версии 252/255 не считается подтверждением наличия `resolvectl`. GI typelib
имеет собственную версию (в Ubuntu 22.04 — 1.72); минимум GIO задаётся через
`libglib2.0-0` / `libglib2.0-0t64`, а не версией `gir1.2-glib-2.0`.

На Debian установка зависимости `systemd-resolved` может сама переключить
системный resolver средствами пакета `systemd-resolved`. Скрипты Quantway
DNS не перенастраивают: не меняют `/etc/resolv.conf`, не включают и не
перезапускают DNS-службы.

Secret Service в пользовательской D-Bus-сессии нужен для сохранения входа;
рекомендован GNOME Keyring. При недоступном хранилище приложение сохраняет
рабочую сессию только в памяти и предлагает повторить сохранение.

## Установка, обновление и удаление

Например, для ARM64: `sudo apt install ./quantway_0.7.1~preview20261101.2_arm64.deb`.
Для AMD64 используется соответствующий файл с суффиксом `_amd64.deb`.
Запускайте Quantway из меню приложений либо командой `quantway` обычным
пользователем. Установка не подключает VPN и не создаёт автозапуск.

Перед установкой поверх существующей версии, обновлением или удалением
отключите VPN и закройте Quantway во всех пользовательских сессиях.
Maintainer scripts делают неблокирующий `flock` только для уже существующего
`/run/quantway-desktop-vpn.lock`: файл должен быть обычным, `root:root`, `0600`,
с одним hard link. Они не создают, не удаляют и не подменяют файл блокировки.
Занятое или небезопасное состояние вызывает отказ; ничего не останавливается.

Проверка одноразовая: она не удерживает блокировку на протяжении транзакции
dpkg и не обещает устранить гонку с новым подключением после проверки.
Закрытый клиент должен оставаться закрытым до окончания операции. Настоящая
блокировка одновременных VPN-сессий остаётся внутри сетевых помощников.

Скрипты не запускают и не убивают процессы VPN, не перезапускают приложения,
не устанавливают разрешающие правила PolicyKit и не модифицируют маршруты,
firewall или DNS. Отдельные `postinst`/`postrm` для VPN не нужны; при обновлении
desktop/icon caches допустимы только обычные операции кеширования.

Удаление и purge сохраняют пользовательские данные, Secret Service и ключи
устройств в `/var/lib/quantway-tinc/users/`. Стирание ключа без согласованной
смены идентичности устройства приводит к конфликту на сервере. В пакет не
включаются учётные данные, cookies, ссылки подписок, private keys или runtime
state.
