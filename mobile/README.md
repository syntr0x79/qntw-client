# Android клиент Quantway

Android приложение включает системный VPN через Xray и AmneziaWG, мобильный пробер и встроенный существующий кабинет. Пробы используют физическую сеть и могут выполняться при работающем VPN. При смене сети приложение восстанавливает туннель и автоматически продолжает запущенную проверку.

## Сборка

Нужны Go из корневого go.mod, JDK 17, Android SDK Platform 35, Build Tools 35.0.0 и NDK 28.0.13004108. Go библиотека находится в отдельном модуле, чтобы инструменты Android не обновляли зависимости backend. Версии Xray и AmneziaWG берутся из существующего backend.

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export ANDROID_HOME="$HOME/Library/Android/sdk"
export ANDROID_NDK_HOME="$ANDROID_HOME/ndk/28.0.13004108"
./mobile/scripts/build-engine.sh
cd mobile/android
./gradlew assembleDebug
```

Результат: `mobile/android/app/build/outputs/apk/debug/app-debug.apk`. AAR и результаты сборки исключены из Git. Сборка включает ARM64 для телефона и x86_64 для соответствующих эмуляторов.

## Запуск внутреннего пилота

Backend включает мобильные ручки только при `MOBILE_PROBE_ENABLED=1`. Мобильный контрольный адрес по умолчанию — HTTPS `SUBSCRIPTION_BASE_URL/api/mobile/v1/check`; его можно заменить через `MOBILE_PROBE_CONTROL_URL`. Серверный `PROBE_CONTROL_URL` не меняется. Миграции 0120–0122 создают отдельные таблицы мобильных прогонов, отчётов и AWG пиров пробера. Существующие голоса маяков не меняются.

На экране вводится одна полная HTTPS ссылка подписки конкретного устройства `/sub/{token}`. Клиент сам получает origin и токен из ссылки; endpoint `/api/mobile/v1/profiles` выдаёт доступные профили через существующий Selector. Это временная авторизация пилота: токен разрешает только доступ устройства к конфигурации и отправку его измерений. Он не даёт права управлять аккаунтом. Ссылки и кеш конфигураций сохраняются в закрытом noBackup хранилище с AES-GCM и ключом Android Keystore; обычные preferences содержат только настройки интерфейса. Перед публичным выпуском нужна отдельная привязка установки и мобильная сессия.

Приложение проверяет до шести заданий последовательно, с бюджетом 30 секунд на прогон. Отправка отчётов выключена по умолчанию. При включении отчёт сохраняется до отправки и повторяется с тем же report_id. Отчёты не содержат ключей или исходных текстов ошибок движка. При сетевом сбое очередь можно отправить кнопкой на экране; автоматический WorkManager ещё не подключён.

Системный VPN использует VpnService и нативный TUN. Для AWG с правилами обхода Xray маршрутизирует потоки в защищённый AWG netstack; при отключённых правилах остаётся прямой AWG TUN. AWG пробы получают отдельный peer и адрес, поэтому не перехватывают действующее подключение устройства. Смена физической сети прерывает только текущие измерения: после появления сети пробер запрашивает новый прогон с новым epoch. Туннель проверяет доступность и восстанавливается с перебором доступных профилей. Периодический фоновый сбор и выдача скрытых экспериментальных масок пока не подключены.

Кнопка кабинета открывает существующий `/account` во встроенном браузере с обычным входом. Подписочная ссылка не даёт доступа к управлению аккаунтом. В консоли экран «Телефоны» показывает агрегаты мобильных измерений за 24 часа отдельно по сети и версии движка, без влияния на доверенные голоса маяков.

Прогоны хранят метаданные выданных заданий без секретных payload. Отчёт принимается целиком один раз на прогон. Изменённый повтор получает 409; неверная пара, другой network_epoch или истёкший прогон — 400. Получение заданий ограничено одним прогоном в минуту в пределах epoch и интервалом не менее пяти секунд между любыми прогонами устройства. Для таблиц пилота перед массовым включением нужен плановый сборщик устаревших данных.

## Проверки

Из корня репозитория:

```sh
go test ./internal/web ./cmd/shop
go test -race ./internal/mobileprobe/... ./internal/xrayfetch ./internal/beaconagent
cd mobile
go test -race ./engine
```

Интеграционные backend тесты используют PostgreSQL из `docker compose up -d --wait postgres`. Без него они явно пропускаются. Привязка сети и смена Wi-Fi на мобильную сеть проверяются на эмуляторе. Поведение реального оператора и расход батареи требуют последующей проверки на телефоне.

В Android сборке используется флаг линковщика `-checklinkname=0`, требуемый транзитивной библиотекой [anet](https://github.com/wlynxg/anet) для Go 1.23 и новее. При смене Go или x/net нужно повторно проверить совместимость её кешей сетевых интерфейсов.

На запущенном Android эмуляторе проверка нативного моста:

```sh
cd mobile/android
./gradlew connectedDebugAndroidTest
```

Она проверяет вызов Android DNS и привязки сокета из Xray, а также классификацию некорректного AWG конфига. Это не проверка доступности рабочих VPN узлов. Для реальных подключений нужен включённый мобильный API и токен устройства.

В дополнительной проверке с `-race` существующий `TestProbeAgainstInProcessServer` пакета awgprobe превышает свой порог 900 мс; обычный прогон проходит. Изменение этого порога в первый срез не входит.

## Сквозной стенд на эмуляторе

При запущенном ARM64 AVD, PostgreSQL и установленной AAR можно выполнить из корня:

```sh
ANDROID_EMULATOR_TEST=1 go test -count=1 -v -timeout 10m ./internal/web -run '^TestAndroidEmulatorRoundTrip$'
```

`JAVA_HOME` и `ANDROID_HOME` должны быть заданы как в инструкции сборки. `ANDROID_TEST_GRADLE` позволяет указать установленный Gradle вместо wrapper. Цель `make mobile-emulator-test` также пересобирает AAR.

Тест создаёт изолированную БД и временные узлы Reality, XHTTP и AWG. Пять Android сценариев проверяют реальный HTTPS через протоколы, запись и идемпотентность отчётов, отмену отдельной пробы при смене сети, системный VPN через Xray и AWG, параллельную AWG пробу с независимым peer, переключение сети, импорт полной ссылки и автоматическое продолжение пробера. Встроенный браузер также проверяется через оба туннеля. Для контрольного HTTPS и цели Reality требуется доступ в интернет.

Внутри AWG стенд принимает DNS только для example.com и пересылает зашифрованное HTTPS соединение к настоящему example.com без отключения проверки сертификата. Он обслуживает публичные IPv4 адреса сайта, чтобы кеш браузера сохранял корректное назначение при смене туннеля. Тест смены сети открывает соединение с молчащим узлом, отключает Wi-Fi эмулятора и проверяет, что результат считается прерванным, а не отказом маски. Wi-Fi восстанавливается после теста.

Локальный API стенда доступен через специальный адрес хоста эмулятора 10.0.2.2. HTTP к этому адресу разрешён только debug manifest; основной клиент по-прежнему принимает HTTPS origin.

## Интерфейс 0.3.0

Четыре основных раздела: VPN, маршруты, подписки, настройки. Дополнительные экраны: импорт, проверка маршрутов, сведения о соединении, обход VPN, личные доменные исключения, диагностика, подготовка отчёта, помощь и сведения о приложении. Главный экран использует выбранный дизайн с круглой кнопкой VPN; светлая и тёмная темы сохраняются, основная тема — тёмная.

Дни и статус подписки, протоколы и общая политика маршрутизации приходят из profiles. Задержка показывается только по реальным измерениям в текущем network epoch; после смены сети старые значения помечаются. При работающем VPN пробер предлагает маршрут, а его применение требует подтверждения. Вручную выбранный маршрут не заменяется фоновым перебором других стран.

Поддерживаются несколько сохранённых подписок. Внешняя ссылка загружается напрямую с телефона; импортируются обычные и Base64 списки VLESS, Hysteria2 и AmneziaWG. Clash YAML и другие форматы не импортируются; пропущенные конфигурации учитываются отдельно. Измерения внешних профилей не передаются в backend Quantway. Оплата, пауза и устройства доступны через существующий кабинет с отдельным входом.

Обход VPN использует те же списки internal/lists, что остальные форматы подписки: принудительный tunnel по домену, затем direct по домену и GeoIP. Личные исключения идут первыми. DNS-сервер AWG явно остаётся в туннеле. Изменения правил применяются при следующем подключении или по подтверждённой команде переподключения. Публичный IPv6 через VPN пока блокируется, как в действующей политике парка.

AppNavigationTest проверяет импорт и шифрование, AWG с правилами, HTTPS через системный TUN и прямой доступ к локальному API, подтверждение смены маршрута, темы, исключения, параллельный пробер, безопасный отчёт и внешний импорт. Общий стенд также сохраняет скриншоты в системном временном каталоге vpnshop-mobile-ui.

## Отложено: IPv6 mesh

Mesh телефонов и собственные IPv6 релеи пока записаны в архитектурный план. IPv4 входы и выходы переиспользуют существующие VPN узлы; отдельные IPv4 серверы не нужны. Доступность входящего IPv6 проверяется отдельно от наличия адреса. Передача чужого трафика через телефон требует отдельного режима и лимитов.
