# План: клиентский слой tinc

Дата: 31.10.2026. Отдельный Linux pilot развёрнут и прошёл live-приёмку с явным допуском до 16 устройств. Активны пять pilot units: два входа, основной и резервный выходы PL, выход SE; документы подтверждены точным ACK. Работают постоянный backend, runtime, учёт и Linux CLI/GTK-клиент с вкладкой Tinc в боковой навигации сразу под «Главная». Основное приложение магазина и PostgreSQL не перезапускались. Итоги и границы: [отчёт pilot](../../audits/2026-10-31-client-tinc-pilot.md).

Основание: [спецификация](../specs/2026-10-31-client-tinc-layer-design.md). Первые native/Android доказательства и ограничения: [отчёт этапа 0](../../audits/2026-10-31-client-tinc-stage0.md). Эксплуатация: [отдельный комплект pilot](../../../deploy/tinc-client/README.md), [Linux CLI](../../../mobile/clienttinc/README.md).

Приложение получает весь каталог входов нового слоя, а backend назначает выход в выбранной пользователем стране. Выбор независим для каждого устройства. Транзит выполняют серверы. Продуктовая цель сохраняется: ПК и ТВ держат связи со всеми входами, телефоны динамически выбирают активный набор. Полный клиентский путь реализован в Linux CLI и существующем GTK-клиенте через отдельный привилегированный помощник.

## 0. Проверенный путь пакетов и границы pilot

- [x] Поднять отдельный стенд с двумя клиентами, тремя входами и выходами A1/A2 в одной стране и B1 в другой. Служебный qmesh не подключать. `test/clienttinc` прошёл 53 проверки в режимах TCP/UDP и TCPOnly с relay-патчем.
- [x] Проверить авторизованный VLESS/TLS до назначенного выхода поверх tinc: реальный TCP HTTP, UDP DNS, проверка TLS-имени и сертификата, отказ чужому устройству и неизвестному credential.
- [x] Выбрать сегментацию для малого pilot: отдельный edge-процесс устройства на каждом входе, серверный core без клиентских пиров, серверный SNAT и авторизация на выходе. Проверены подмена source IP, межклиентский доступ и обход через underlay.
- [x] Проверить native packet-FD и подготовку внешних сокетов при действующем Android VpnService. Упакованные target-35 executable работают из `nativeLibraryDir`; реальные `protect` и `Network.bindSocket` проходят до ACK0.
- [ ] Закрыть полный пользовательский путь через системный Android TUN, внутренний VLESS/TLS и разрешённый выход, включая TCP/UDP/DNS. Android socket guard и raw packet-FD стенд покрывают только часть этого пути.
- [ ] Сравнить стоимость выбранного внутреннего туннеля с альтернативами и прямой IP-доставкой tinc. Основной кандидат для pilot уже выбран; полное сравнение пока не выполнено.
- [ ] Проверить Apple Network Extension, упаковку native-компонентов и условия распространения на всех целевых платформах.
- [ ] Определить производственный масштаб, стоимость графа и процессов, целевые MTU/время восстановления, расход телефона и фоновую активность. Лимит pilot 16 устройств ограничивает допуск, но не является результатом нагрузочного теста на 16 устройствах.

SNAT на входе позволяет возвращать трафик без рассылки клиентских подсетей всему core. Смена входа восстанавливает новые внутренние соединения с тем же выходом; сохранение уже открытого внутреннего TCP-сеанса эта схема не гарантирует. При смене выхода ожидаемо меняются внешний IP и часть сессий.

## 1. Устройства, inventory и права

- [x] Добавить отдельные `client_tinc_nodes` и `client_tinc_devices`, связанные с существующими topology и device_id. Допуск закрыт по умолчанию, оператор выделяет один из 16 стабильных слотов.
- [x] Связать tinc public key с устройством. Первая регистрация и повтор того же ключа идемпотентны; неявная замена ключа запрещена. Private keys устройства и серверов не передаются backend.
- [x] Хранить страну, конкретный выход, версию назначения, отдельный VLESS UUID и абсолютный срок разрешения. При смене страны/выхода вращаются версия и внутренний credential; остальные устройства сохраняют свои назначения.
- [x] Проверять активную подписку, баланс дней, блокировку/отзыв устройства, pool и гарантированный slot входа и выхода. Дополнительный выход разрешён только через фактическое членство в существующем маршруте.
- [x] Отделить права от доступности старых масок: новый tinc использует entitlement и включённую topology без обязательного legacy UUID или успешной старой VLESS/AWG-пробы. Доступность нового слоя определяется отчётами его узлов.
- [x] Добавить общие версионные документы `internal/clienttincwire` и отдельные additive migrations `0126_client_tinc.sql`, `0127_client_tinc_usage.sql`.
- [ ] Добавить управляемую ротацию ключей и сертификатов с явным переносом доверия. Сейчас сохранённые public key/certificate anchors неизменяемы; удаление локальных ключей не выполняется автоматически.

Реальные PostgreSQL-тесты с race detector проверяют независимые устройства, immutable keys, недоступные старые протоколы, pool/slot, подмену node/device identity и закрытый allowlist.

## 2. Серверный runtime

- [x] Выделить core `10.76.0.0/24`, edge `10.77.0.0/16`, интерфейсы `qctcore`/`qce01`…`qce16`, собственную таблицу `inet qct_client`, TCP/UDP 17444 и per-device 17445…17460. Внутренний TLS listener использует 18443; StatsService слушает только loopback 18444.
- [x] Реализовать отдельный `clienttinc-agent`: desired document, локальная генерация ключей/сертификата, собственные процессы tinc/Xray, точный applied revision и независимый watchdog.
- [x] Ограничить доступ edge к сервисам слоя, запретить клиентский транзит, source spoofing, чужие устройства и управляющие адреса. Изолированный стенд сохраняет обычный сервис и исходные firewall rules до, во время и после pilot.
- [x] Выдавать клиентский config после свежего точного ACK назначенного выхода и хотя бы одного рабочего входа. Весь каталог сохраняется, включая известные ключи временно недоступных входов; начальная неизвестная identity требует подготовки.
- [x] Держать lease до пяти минут. Кеш и ошибки API не продлевают срок. Удалённые/заблокированные/неактивные устройства исключаются из документов; смена ACL закрывает старые соединения pilot.
- [x] Продлевать outer и individual lease без перезапуска процессов при неизменной сетевой политике, identity и credential. Canonical NodeRevision сохраняет точное подтверждение нового срока, а runtime сравнивает отдельный semantic fingerprint. Проверен 40-секундный TCP-поток через продление и неизменные native PID. Неуспешное применение не возвращает отозванный credential.
- [x] Выполнить live preflight и приёмку пяти узлов: свободные диапазоны/порты, точный applied ACK, сохранение старых VPN PID и всех исходных статических firewall rules. Ранее занятый AWG диапазон из другой routing table сохранён; pilot использует проверенные 10.76/10.77. Global/physical forwarding не расширяется.

Серверный установщик ставит только новый комплект и systemd unit. Запуск `quantway-client-tinc` — отдельное действие после inventory и allowlist. Обычные Xray, qmesh и host-agent не перезапускаются.

## 3. Backend и API

- [x] Реализовать device Bearer API `identity`, `country`, `config` и независимый node Bearer API `document`, `report` под `/api/client-tinc/`.
- [x] Сохранять назначенный здоровый разрешённый выход, выбирать замену внутри той же страны и обновлять credential/версию. Если вся страна недоступна, ждать восстановления либо явного выбора пользователя.
- [x] Сохранять страну/выход при смене входа. Проверены full catalogue при частичном отказе входов, независимые страны и автоматический A1→A2 без изменения второго устройства.
- [x] Обновлять config каждые 15 секунд; отказы API не превращаются в новый lease. HTTPS API и его физический DNS имеют собственный сетевой путь.
- [x] Подготовить отдельный `clienttinc-control` sidecar: ограниченный DB pool, только pilot migrations, отдельный loopback upstream и собственный Compose project. Shop/billing workers внутри него отсутствуют.
- [ ] Добавить выбор по измеренной свободной мощности и стабилизацию на основе доверенных end-to-end проверок нового выхода. Сейчас используются entitlement/slot и свежие runtime reports, без динамического load/RTT оптимизатора.
- [ ] Отдельно классифицировать отказ входа, серверного участка и internet egress реальными измерениями. Успешное применение runtime само по себе не является доказательством доступности любого интернет-сайта.

## 4. Linux CLI и общая клиентская политика

- [x] Реализовать самостоятельный `mobile/clienttinc` и `mobile/cmd/quantway-tinc`, отдельно от текущего Linux GUI и `mobile/engine`.
- [x] Поднять настоящий пользовательский TUN, VLESS/TLS и overlay TUN с guarded native tinc. Проверены системные TCP/UDP, обе страны, все три входа, смена страны и автоматическая замена выхода.
- [x] Привязать внешние sockets/API DNS к физическому интерфейсу и marked routing table, разрешить внутренний выход только через overlay. При expiry сохранить блокирующий пользовательский TUN/filter до явного stop.
- [x] Реализовать приватный Unix control socket, `connect/status/country/check/stop`, безопасный credential file, ограничение срока, очистку собственных маршрутов/DNS/интерфейсов.
- [x] Встроить режим в существующий Linux GTK-клиент: отдельная вкладка Tinc в боковой навигации сразу под «Главная», страны из device catalog, подтверждение смены страны/режима, единый жизненный цикл и обработка cleanup ошибок. GTK остаётся непривилегированным; root helper работает по приватному IPC. [Приёмка GUI](../../audits/2026-10-31-client-tinc-linux-ui.md).
- [ ] Связать новый режим с общим межплатформенным TunnelController для последующих Android/Apple/Windows адаптеров.
- [ ] Перенести текущие доменные списки обхода и личные исключения. Сейчас Linux CLI является отдельным full IPv4 VPN-режимом; пользовательский IPv6 блокируется.
- [ ] Реализовать восстановление после смены физической сети/сна и безопасный production crash recovery. Первый запуск выполняется в отдельном namespace/VM; после SIGKILL фильтр может намеренно сохраниться.

## 6. Учёт и приёмка

- [x] Снимать пользовательские counters только на авторизованном pilot egress. Отдельный loopback Xray StatsService, epoch на перезапуск процесса, абсолютные totals по устройству/версии/epoch/московским суткам и приватный дисковый outbox.
- [x] Проверять node authentication и историю выданных egress grants, затем атомарно добавлять дельты в существующую `traffic_daily`. Повторы и перестановка запросов не удваивают расход; отрицательные значения, чужие назначения и overflow отклоняются.
- [x] Разрешить доставку финальных измеренных counters до 24 часов после expiry права. Это только окно приёма статистики; сетевой доступ не продлевается. Просроченный outbox явно отбрасывается с диагностикой.
- [x] Проверить на реальной БД duplicate/reset epoch/concurrency/MSK boundary/closing batch/overflow rollback. В интеграционном стенде counters обоих устройств положительны, `traffic_daily` равна сумме cursor totals, ingress пользовательский расход не создаёт.
- [x] Прогнать `TestBackendRuntimeAndSystemClient`: постоянная БД, авторизованный API, шесть реальных server agents и два Linux CLI с системными TUN. Последний подтверждённый расширенный прогон — 46 проверок, 135,72 с, `/private/tmp/clienttinc-integrated-prefix76.log`; сохранены legacy AWG routes в non-main table и непрерывный TCP-поток через продление lease.
- [x] Повторить интеграционный прогон с global forwarding=0 на всех шести серверах: `eth0`/`wan0` сохраняют 0, forwarding разрешён только на собственных pilot-интерфейсах; после expiry/cleanup baseline восстановлен.
- [x] Подтвердить live Linux system TUN в отдельном контейнере с ограниченными capabilities: PL → SE → PL, оба входа, UDP DNS и явный stop с удалением двух TUN/nft и восстановлением физического IP. В PostgreSQL реальные counters PL/SE совпали с cursor totals; на входах пользовательский расход равен нулю. Обычные shop/API/PostgreSQL и ранее работавшие VPN сохранены. [Live evidence](../../audits/2026-10-31-client-tinc-pilot.md).
- [ ] Выполнить нагрузочные измерения на предельном числе устройств/входов, оценить рост процессов и графа, мобильный RTT и расход энергии.
- [ ] Открыть массовый пользовательский режим после GUI, платформенных приёмок и подтверждённых бюджетов. Pilot allowlist не включает остальных покупателей автоматически.

Проверки backend/runtime и инструкции воспроизводимы из репозитория. Live-приёмка завершена для ограниченного Linux pilot. Android full TUN, остальные платформы, мобильный RTT и массовое масштабирование остаются следующими этапами.
