# Клиентский Tinc: общий допуск устройств

Дата: 2026-10-31.

Общий допуск включён в продакшене: `CLIENT_TINC_OPEN_ENROLLMENT=true` сохранён в `control.env`. Все пять пилотных узлов обновлены и подтвердили актуальные документы. Проверены backend, стенд с 16 активными клиентами и готовое Linux-приложение с настоящим производственным подключением. Основной магазин, PostgreSQL и прежние VPN сохранили процессы и настройки.

## Допуск и ёмкость

`CLIENT_TINC_OPEN_ENROLLMENT` по умолчанию выключен. При включении устройство с действующим Bearer-токеном, активной подпиской и доступными днями может получить каталог и зарегистрировать ключ без ручного разрешения оператора. Блокировка или отзыв устройства, явный административный запрет, доступные пулы и закреплённый за тарифом узел продолжают проверяться.

Доступность режима для аккаунта не резервирует серверное место:

| Операция | Сохраняемое состояние |
| --- | --- |
| `GET /catalog` | Только чтение; не создаёт строку устройства или аренду |
| `POST /identity` | Неизменяемый публичный ключ и тип устройства; `slot=NULL` |
| `POST /country`, последующее получение конфигурации | Аренда одного из 16 мест, выбранная страна и назначенный выход |

Места выдаются атомарно под общей блокировкой PostgreSQL и проверкой версии предыдущего состояния. Сначала выбирается свободное место; при заполнении — место с завершившейся не менее 120 секунд назад арендой. Действующая аренда другого устройства не отбирается. Освобождение места сохраняет ключ, выбранную страну и историю учёта прежнего устройства.

Новая, повторно выданная или уже истёкшая аренда всегда получает новую версию и внутренние данные доступа. Обычное продление действующей аренды сохраняет их. Клиентская конфигурация выдаётся после точного подтверждения нового документа назначенным выходом и хотя бы одним доступным входом. Предел аренды — пять минут; ошибка API не продлевает уже полученную клиентом конфигурацию.

| Условие | Ответ API |
| --- | --- |
| Недействительный токен | `401` |
| Неактивная подписка | `402` |
| Запрет доступа | `403`, `code=access_denied` |
| Все 16 мест заняты | `503`, `code=capacity_exhausted`, `Retry-After: 10` |
| Ожидание серверной конфигурации | `503`, `code=configuration_preparing`, `Retry-After: 2` |

Каталог сохраняет прежнюю схему стран и состояний; он не раскрывает серверные адреса или учётные данные.

## Хранение и совместимость

Миграция `0128_client_tinc_open_enrollment.sql` разрешает `NULL` в `slot` и добавляет `open_enrolled BOOLEAN NOT NULL DEFAULT false`. Существующие ручные разрешения, ключи и места не переписываются. Значение `allowed` по умолчанию остаётся `false`; массового создания устройств, изменения подписок или начислений нет.

Автоматически зарегистрированные устройства помечаются `open_enrolled=true`. Выключенный флаг исключает их из клиентского допуска и документов узлов. Явный административный запрет действует даже до первой регистрации; ручное разрешение снимает признак автоматического допуска.

Документы узлов читают только строки с занятой и действующей арендой: максимум 16 устройств. Вход публикует неизменяемый общий публичный ключ для новых изолированных подключений. Прежние индивидуальные ключи сохраняют приоритет. Это позволяет подготовить каталог входов для нового устройства без создания постоянного серверного ключа для каждого аккаунта.

Локальный журнал: `/private/tmp/clienttinc-open-race.log`.

Новые проверки подтверждают чтение каталога без записи, регистрацию ключа без места, неизменяемость ключа, запрет неизвестного устройства оператором, отключение автоматического допуска флагом, сохранение правил пулов и закреплённых узлов. Из 17 конкурентных подключений ровно 16 получают разные места, одно получает `capacity_exhausted`. Проверены задержка повторной выдачи, отказ устаревшего запроса на продление, сохранение истории, смена версии после истечения и обязательное новое подтверждение узлов. Общий публичный ключ входа закрепляется при первом получении; свёртка одинаковых ключей не меняет переданную вызывающим кодом карту.

## Выключение общего допуска

Безопасный откат — выключить `CLIENT_TINC_OPEN_ENROLLMENT` на совместимом новом контроллере. Он запрещает новые конфигурации автоматически зарегистрированным устройствам и исключает их из документов узлов. Применение документа отзывает соединения; недоступный узел ограничен сроком последней полученной аренды. Ручные разрешения сохраняются.

Добавленную схему, ключи и историю учёта оставляют на месте. Контроллер до миграции 0128 несовместим со строками `slot=NULL`: его старый сканер устройств может отказать при построении документов узлов. Поэтому возврат к такому образу не равнозначен выключению флага. Откат не требует перезапуска основного магазина или PostgreSQL.
