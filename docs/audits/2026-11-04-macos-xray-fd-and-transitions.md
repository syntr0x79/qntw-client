# Исправление Xray и переключения выхода на macOS

4 ноября 2026. Клиент macOS ARM64 0.3.2, build 20261104.2.

## Исправление зависимости

Xray закреплён на [cf54a5a2cafce1dac1aaf1ca7eb19ff145030dee](https://github.com/syntr0x79/Xray-core/commit/cf54a5a2cafce1dac1aaf1ca7eb19ff145030dee), обычный Go replace на `github.com/syntr0x79/Xray-core v1.260327.1-0.20261104110251-cf54a5a2cafc`. Форк начинается с прежнего upstream commit `52a412d9e2f5c2a5142b1b4e2ab3771dacb8b120`; производственное изменение ограничено Darwin TUN, дополнительно добавлены регрессионные тесты.

Ранее `os.NewFile` оборачивал переданный приложением FD, но Xray не закрывал эту обёртку явно. Её финализатор мог позже закрыть исходный или уже переиспользованный дескриптор. Теперь Xray атомарно получает собственный `F_DUPFD_CLOEXEC`-дубликат, закрывает его синхронно и только один раз. Владение дескриптором отделено от владения интерфейсом: внешний системный TUN и маршруты остаются под управлением приложения.

Основной кэш модулей и исходники upstream не изменяются. Сборщик проверяет полный hash архивов исходной и исправленной зависимости, выбранный Go replacement, исходник, patch и тесты. Оба помощника и встроенный framework используют один fingerprint `6abeefe12c24bf0ddf0b1ccb4e76357b270a1031f37d8b4c694d718d10f8df11`. Устаревший framework пересобирается автоматически. Manifest, исходники, patch и лицензия включены в пакет.

Tinc остаётся на `03bfd922c1749b27769a3e3a5680efde64d45af0`. Серверные бинарники, backend API и схема БД этим исправлением не обновлялись.

## Проверки до подключения

- Прежний Xray воспроизводит EBADF после Close/GC при живом дескрипторе вызывающей стороны.
- Исправленный Xray прошёл три теста с race detector: сохранность исходного FD, синхронное закрытие собственного дубликата/CLOEXEC, 32 последовательных цикла с повторным использованием FD и проверку неверного FD.
- Полный `mobile/clienttinc` снова выполняется в одном процессе без workaround с дочерним процессом: 55,053 с, 1024/1024 UDP-источника, последующий TCP, пик 26/64 физических TLS-соединений.
- Go-тесты IPC, команд помощника и CLI; проверка модели подтверждения страны в JavaScript и сборка Swift прошли. Тесты harness отклоняют неверный внешний IP, изменение маршрута/эпохи TUN и сохраняют отрицательные результаты.
- Настоящий gomobile bind и полный клиент собраны; ad-hoc подпись `.app` проверена. Developer ID и нотариализация не выполнялись.

Данные зависимости: [FD fix evidence](artifacts/2026-11-04-xray-darwin-fd-fix.json).

## Смена страны в приложении

После подтверждения смены страны интерфейс отправляет ограниченную команду `country` действующему помощнику через существующий канал с проверкой UID. Процесс и системный TUN не перезапускаются. Контроллер сохраняет прежний путь до получения нового разрешённого назначения и затем перестраивает внутренний data path.

Команды ограничены размером и фиксированным набором действий. Stop/EOF отменяют ожидание авторизации и выполняющуюся сессию. Диагностическая команда принудительной сборки мусора доступна только при явно включённом приёмочном режиме; обычный интерфейс этот режим не включает. В диагностику добавлены PID помощника и версия назначения.

## Живая приёмка через production

Все четыре этапа выполнены в **одном привилегированном процессе PID 8131** и на одном системном **utun7**, с неизменной эпохой счётчика TUN. После каждого подтверждённого назначения выполнена сборка мусора именно в этом процессе, затем два независимых набора запросов обычного пользователя.

| Этап | Страна | Версия назначения | Выход | Результат |
| --- | --- | --- | --- | --- |
| Первое подключение | PL | 3 | outpl | 2/2 |
| Подтверждённая смена страны | SE | 4 | outse | 2/2 |
| Возврат в Польшу | PL | 5 | outpl | 2/2 |
| Автоматическая замена выхода | PL | 6 | outpl2 | 2/2 |

Каждый из восьми наборов подтвердил обычный HTTPS, HTTPS к заранее разрешённому контрольному адресу с проверкой сертификата, UDP DNS, системный DNS и фактический внешний IPv4 назначенного выхода. Маршрут до/после запросов оставался на том же системном TUN. При автоматической замене изменились ID выхода и внешний IP, сохранились страна, PID и TUN. Общая длительность сценария до завершения сессии — 120,34 с.

Для отказа использовано обратимое отключение выбранного PL-выхода в membership только клиентского слоя. Прямое редактирование назначения не применялось. Перед действием проверены отсутствие других клиентов и здоровый альтернативный PL-выход. Независимый монитор на control-host дождался последовательности PL→SE→PL, новой двусторонней статистики текущего назначения, выдержки времени и свежих ACK. Сначала подтверждён активный 120-секундный таймер восстановления, затем выполнен disable-node.

Серверные события: watchdog активен 11:14:00 UTC, отключение выхода подтверждено 11:14:01 UTC, автоматическое назначение другого PL-выхода подтверждено 11:14:17 UTC. Это проверка штатного автоматического выбора при недоступности участника клиентского слоя, а не испытание физического uplink, сна или смены Wi-Fi.

После Stop подтверждены исходный маршрут `en0`, исходное состояние DNS и завершение сетевых процессов. Затем восстановлен исходный PL-выход, сравнены точные enabled-флаги всех 18 узлов, остановлены монитор и таймер. Анонимный canary отозван. Платежи и реальные пользовательские аккаунты не использовались.

Финальная read-only сверка подтвердила 18/18 исходных enabled-флагов, свежие applied/exact ACK, работающую службу восстановленного outpl, фактический hash tinc и все его 17 core-соседей. Canary имеет allowed=false, API каталога возвращает 403, используемых тестовых разрешений нет. Остаточных monitor/watchdog units не найдено. [Production postcheck](artifacts/2026-11-04-macos-xray-production-postcheck.json).

Первая попытка не получила системное подтверждение администратора до deadline. Привилегированный помощник не запускался, событий/смены маршрутов не было; монитор отменён без отключения узла. Отрицательный результат этой попытки сохранён отдельно. Повторный полный сценарий имеет `passed=true`.

Данные: [live transitions](artifacts/2026-11-04-macos-xray-transitions-live.json), [серверное восстановление](artifacts/2026-11-04-macos-xray-failover-restoration.json), [ожидание системного подтверждения](artifacts/2026-11-04-macos-xray-transitions-authorization-timeout.json), [build result](artifacts/2026-11-04-macos-xray-build.json).
