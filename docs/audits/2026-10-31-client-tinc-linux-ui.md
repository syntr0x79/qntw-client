# Tinc в Linux-клиенте Quantway

Дата: 31.10.2026. Реализована отдельная страница **Tinc**, доступная в боковой навигации сразу под «Главная» существующего GTK-клиента. Главная страница обычного подключения, кабинет и сторонние провайдеры сохранены.

## Поведение

Страны поступают из авторизованного `GET /api/client-tinc/v1/catalog`, с учётом текущего устройства, allowlist, подписки, pool/slot и готовности серверов. Список работает до регистрации ключа. Endpoint не продлевает разрешение и не публикует credentials, серверные адреса или конфигурации.

Страница показывает страну выхода, подключение/отключение, состояние и число подключённых входов. Смена страны при активном VPN требует подтверждения. Смена обычного режима и Tinc ждёт завершения старого помощника; ошибка очистки запрещает запуск нового режима. При потере привязки аккаунта или устройства остаётся доступно отключение, устаревшие callbacks не меняют новую сессию. Истечение доступа оставляет блокировку до явного отключения. Автоматического перехода на обычный VPN нет.

Tinc доступен только для текущего устройства Quantway. Ссылки сторонних провайдеров не отправляются его API. Массовый допуск не включался: прежний ограниченный пилот до 16 устройств сохраняется.

## Системный помощник

GTK и `quantway-helper` работают от обычного пользователя. Отдельный фиксированный `quantway-tinc-helper` запускается через настоящий pkexec. Credentials передаются только в памяти через приватный SOCK_SEQPACKET на stdin; в argv, логи и временные файлы не попадают. Root проверяет SO_PEERCRED, вызывающий UID, собственность/права исполняемых файлов, сообщения и фиксированный API origin.

Ключ устройства хранится в root-only каталоге по UID и авторитетному DeviceID. Ротация ссылки сохраняет ключ. Общий root lock исключает одновременное владение сетью двумя помощниками. Старый `quantway-net-helper` продолжает принимать только сетевые параметры без VPN credentials.

При живой приёмке найден и устранён конфликт глобального Xray dialer: новый helper косвенно импортировал старый engine через privsep. Теперь его private socketpair не зависит от engine, добавлены регрессия настоящего DialSystem и проверка графа зависимостей при сборке. Для долгого режима закрываются idle HTTP connections после локальных country-команд и health probes.

## Сборка и установка

`mobile/scripts/build-linux-client.sh all` собирает ARM64/AMD64 пакеты в `bin/quantway-linux-client`. Пакет содержит существующий GTK-клиент, три Go-помощника, закреплённый guarded tinc, лицензию, brand asset, сведения об исходниках и SHA256SUMS. Credentials и state отсутствуют.

Установщик проверяет весь manifest, архитектуру ELF, отсутствие симлинков и root-owned целевые каталоги. Четыре привилегированных бинарника устанавливаются атомарно в `/usr/libexec/quantway` с правами root:root 0755. Проверены строгий `umask 077`, доступ UID1000, исправление собственного каталога 0700 → 0755, отказ при подмене, симлинке или небезопасном внешнем каталоге. Установка не запускает VPN и не добавляет разрешающие polkit rules.

В текущем checkout ARM64 файлы `mobile/linux/build` обновлены атомарно, предыдущие бинарники сохранены отдельно. Для пользовательского компьютера требуется однократная установка помощников через `mobile/linux/setup-vm.sh`; само приложение запускается обычным пользователем через `run.sh`.

## Проверки

- Backend: 16 реальных PostgreSQL/race-проверок каталога, API и учёта, плюс vet.
- Linux/race: clienttinc, tincvpn, netlock и dedicated helper; UID/FD/path guards, EOF/cancel, timeout/late ACK, cleanup ACK, сохранение identity при ротации токена, медленный UI consumer, отсутствие FD-накопления.
- Настоящий GTK: проверки новой страницы, подтверждений, потери binding, старых событий и обоих направлений смены режима; существующие smoke/route/source/auth/device/cabinet тесты. Старый независимый дефект FlowBox на странице устройств воспроизведён и без Tinc; к новой странице он не относится.
- Финальная приёмка собранного пакета: настоящий GTK под UID1000 → настоящий pkexec → root helper → native tinc → реальные пилотные серверы. Кабинетная привязка в этом тесте подставлена без настоящей account cookie; device token, каталог, привилегии и весь путь пакетов настоящие.

Из меню справа открыта вкладка, выбрана Польша, нажато подключение, подтверждены Швеция и возврат в Польшу. Получены реальные выходные IP `199.19.77.43` → `185.130.44.165` → `199.19.77.43`. В обеих странах подключены `inpl`/`innl`, непомеченные UDP DNS проходят системный TUN. Отключение удалило TUN и восстановило прежний интернет тестового namespace.

Использованы реальные dbus/polkit/systemd-resolved в отдельном Linux-контейнере с NET_ADMIN/NET_RAW и `/dev/net/tun`. Тестовое правило автоматического разрешения pkexec существует только внутри одноразового контейнера; в клиент не поставляется. Основная desktop VM и сеть компьютера не изменялись. Production проверки отказов/отзыва выполнялись на прежнем изолированном стенде, живые серверы не отключались.

Результат: `/private/tmp/quantway-tinc-gui/final-live-gui.log`, локальные snapshots и result.json. Тестовые credentials и ключи сохранены только в приватных файлах/отдельном volume. Это по-прежнему экспериментальный Linux IPv4 режим; мобильные платформы, GUI crash recovery, смена физической сети и массовое масштабирование остаются отдельными этапами.

## Итог production

После GUI-приёмки повторно сохранены доказательства: shop/PostgreSQL сохранили ID и StartedAt и остаются healthy, nginx master PID прежний, `https://qntw.link/` отвечает 200. На всех пяти узлах сохранены прежние статические firewall objects/handles и VPN PID/время старта; global/default/physical/legacy forwarding остаётся 0. Все пять pilot units активны и присылают свежий точный ACK.

У нового тестового устройства на момент финальной проверки: PL — 12 001 байт вверх / 35 501 вниз, SE — 2 586 / 7 895. На обоих входах и резервном неиспользованном выходе пользовательский расход 0; `traffic_daily` точно совпадает с суммой cumulative cursor. Живые проверки не перезапускали старые службы и не меняли обычные VPN.

Тестовые контейнеры удалены после успешного отключения; приватные ключи и proof остались только в выделенных закрытых каталогах/volume для повторного canary. Готовые архивы проверены по SHA256, исходники и бинарники в финальном пакете совпадают.

## Уточнение расположения

По уточнению пользователя пункт Tinc перенесён из отдельного меню заголовка в существующую боковую навигацию, сразу после «Главная». Добавленное меню заголовка удалено. Проверяются порядок пунктов, активное состояние вкладки и переходы между прежними разделами; сетевые компоненты не менялись. Первоначальная живая сетевая приёмка выше относилась к тому же экрану до переноса точки входа.
